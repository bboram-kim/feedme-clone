# 저장한 글 보관 방식

## Decisions

- 변환한 글의 저장은 로그인한 사용자가 직접 저장 동작을 할 때만 일어납니다. 변환만으로는 아무것도 저장되지 않습니다.
- 저장한 글은 Supabase에 계정별로 보관합니다. 본인 글만 읽고 지울 수 있고, 다른 사용자와 비로그인 요청은 접근할 수 없습니다(`profiles`와 같은 owner-only 방식).
- 저장은 변환 시점의 스냅샷입니다(원본 URL, 제목, 저자, 사이트, Markdown 본문). 저장한 글을 다시 볼 때 원본 페이지를 다시 가져오지 않습니다.
- 로그인하지 않은 사용자의 변환과 ChatGPT·Claude 전달은 지금처럼 그대로 쓸 수 있습니다.

## Boundaries

- 저장한 글의 공유, 폴더·태그, 검색, 편집은 이 결정이 정하지 않습니다.
- 변환 요청 기록을 자동으로 남기는 결정이 아닙니다.

## Why

"내가 저장한 글"은 기기를 바꿔도 따라와야 의미가 있고, 로그인과 Supabase가 이미 있어 계정별 보관의 추가 비용이 작습니다. 이전 계약의 "서버 저장과 계정을 두지 않는다"는 로그인 도입(PR #2)으로 전제가 사라졌고, 저장을 사용자 동작으로 한정해 "변환만으로는 흔적을 남기지 않는다"는 원래 의도는 유지합니다.

## Reconsider when

- 저장 용량이나 비용이 부담될 만큼 쌓일 때
- 원문 갱신을 따라가야 한다는 요구가 생길 때(스냅샷 대신 재변환)

## Still-rejected alternatives

- 브라우저 localStorage에만 저장 — 로그인 없이 되지만 기기·브라우저를 바꾸면 목록이 사라지고 저장 용량 한계가 있습니다.
- 변환할 때마다 자동으로 기록 — 사용자가 고르지 않은 글이 쌓이고 개인정보 부담이 커집니다.
