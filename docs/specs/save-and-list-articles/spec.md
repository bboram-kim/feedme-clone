# 변환한 글 저장과 저장한 글 목록

## 사용자에게 보이는 결과

로그인한 사용자는 변환 결과 화면에서 글을 저장할 수 있고, 나중에 "저장한 글" 목록에서 다시 열어 읽고 ChatGPT·Claude로 넘길 수 있습니다. 기기를 바꿔 로그인해도 같은 목록이 보입니다.

## 연결된 결정

- [saved-articles](../../decisions/saved-articles.md): 저장 시점, 계정별 보관, 스냅샷, 비로그인 사용 유지를 정합니다. 이 스펙은 규칙을 다시 적지 않고 그 계약을 따릅니다.
- [page-extraction-and-llm-handoff](../../decisions/page-extraction-and-llm-handoff.md): 변환과 LLM 전달 방식. 저장한 글에서도 같은 전달 동작을 씁니다.
- [ui-composition](../../decisions/ui-composition.md): 새 화면과 상태 표현의 구성 기준.

## 범위

- 변환 결과 화면에 "저장" 동작을 추가합니다.
- "저장한 글" 목록 화면과, 목록에서 연 글의 상세 화면을 추가합니다.
- 저장한 글을 삭제할 수 있습니다.
- 메인 화면 상단에서 "저장한 글"로 이동할 수 있습니다.

## 인수 기준

1. 로그인한 사용자가 변환 결과에서 저장하면 성공 알림이 보이고, 같은 결과에서 저장 동작이 "저장됨" 상태로 바뀝니다.
2. 같은 사용자가 같은 URL을 다시 저장하면 목록에 항목이 늘지 않고 기존 항목의 본문과 저장 시각이 새 변환 결과로 갱신됩니다.
3. "저장한 글" 목록은 최신 저장 순으로 제목(없으면 사이트), 사이트·저자, 저장 날짜를 보여줍니다.
4. 목록에서 글을 누르면 상세 화면에서 제목, 저자·사이트, 원본 링크, Markdown 본문이 보이고, 복사·다운로드·ChatGPT/Claude로 보내기를 변환 화면과 같은 방식으로 쓸 수 있습니다. 원본 페이지를 다시 가져오지 않습니다.
5. 저장한 글을 삭제하면 확인 단계를 거친 뒤 목록에서 사라지고, 새로고침해도 돌아오지 않습니다.
6. 사용자 A가 저장한 글은 사용자 B의 목록, 상세 주소, 직접 조회로 접근되지 않습니다. 비로그인으로 목록·상세 주소를 열면 로그인 화면으로 이동하고, 로그인하면 원래 보려던 화면으로 돌아옵니다.
7. 비로그인 사용자는 지금처럼 변환·복사·다운로드·LLM 전달을 모두 쓸 수 있고, 저장 동작에는 "로그인하고 저장"이 보이며 누르면 로그인 화면으로 이동합니다.
8. 저장한 글이 없으면 빈 상태 안내와 변환 화면으로 가는 동작이 보이고, 목록·상세 로딩 중에는 로딩 상태가, 저장·삭제 실패 시에는 오류 알림이 보입니다.
9. 좁은 화면에서도 목록과 저장·삭제 동작이 숨겨지지 않습니다.

## 확정된 제약

- 변환만으로는 저장되지 않습니다. 사용자가 저장을 누를 때만 저장됩니다.
- 앱 UI 문구는 한국어입니다.
- 저장한 글의 프롬프트 선택(요약·번역 등)은 저장하지 않습니다. 보낼 때 다시 고릅니다.

## 가정 (덮어쓸 수 있음)

- 같은 URL의 중복 저장은 새 항목이 아니라 갱신입니다. URL 비교는 입력한 주소 그대로 합니다.
- 로그인하지 않고 "로그인하고 저장"을 누르면 로그인 화면으로 이동하므로 현재 변환 결과는 사라지고, 로그인 후 다시 변환해야 합니다. 변환 결과를 유지하는 일은 하지 않습니다.
- 삭제는 요청 범위는 아니지만 목록 관리에 필요해 포함했습니다. 휴지통·복구는 없습니다.
- 한 사용자가 저장할 수 있는 글 수와 한 글의 크기는 따로 제한하지 않습니다(변환은 이미 5MB 응답 상한).
- 새 테이블 생성은 저장소의 Supabase 마이그레이션으로 하고, 이미 연결된 Supabase 프로젝트에 적용하는 일은 구현에 포함합니다.

## 범위 밖

- 공유, 폴더·태그, 검색, 정렬 변경, 본문 편집, 다중 선택 삭제: 요청되지 않았고 결정 계약도 정하지 않습니다.
- 변환 기록 자동 저장: 계약이 거절한 방식입니다.
- 변환 로직과 LLM 전달 방식 변경.

## 남은 위험

- 로그인 전 변환 결과가 사라지는 흐름이 번거롭다는 반응이 나올 수 있습니다. 그때 결과 보존을 별도 작업으로 다룹니다.
- 저장한 본문이 쌓이면 용량이 늘어납니다. 계약의 재검토 조건에 해당합니다.
